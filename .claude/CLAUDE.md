## Project Overview

Only Once Share (ooshare.io) — a zero-knowledge, one-time secret sharing service. Secrets are encrypted client-side before they reach the server; the server is a blind blob store and never sees plaintext or keys. A secret is atomically deleted on first retrieval.

The repo is a monorepo with **four clients of one shared crypto format**: the web UI, a browser extension, a Go CLI, and a GitHub Action (a separate repository, `dhdtech/ooshare-action`). A link created by any of them opens in the others.

## Architecture

### The crypto contract (the load-bearing part)

Three independent implementations must produce byte-identical output. **`ui/src/lib/crypto.ts` is the source of truth**; the extension imports it verbatim via `@ui`, and `cli/internal/crypto/crypto.go` is a hand-written Go port.

```
Cipher:  AES-256-GCM
KDF:     HKDF-SHA-256, salt "only-once-share-v1", info = the secret ID
IV:      12 random bytes per encryption
AAD:     the secret ID
Wire:    base64( [version 0x01][iv 12B][ciphertext + GCM tag] )
Key:     32 bytes, base64url, carried ONLY in the URL fragment
```

**Payload envelope**, layered inside the ciphertext:

```
text only    [0x00][text UTF-8]
text + file  [0x01][text_len u32 BE][text][mime_len u8][mime][file bytes]
legacy       a first byte other than 0x00/0x01 → the whole payload is raw UTF-8
```

Share URLs are `https://ooshare.io/s/<alias|id>?lng=<lang>#<base64url key>`. The fragment never reaches the server.

**The CLI↔browser interop guarantee** is a set of golden vectors in `cli/internal/crypto/vectors_test.go`, generated by `cli/scripts/gen-vectors.mjs` using Node's Web Crypto with fixed inputs. Regenerate with `node scripts/gen-vectors.mjs` from `cli/`. Any change to the wire format or envelope must update the generator, the vectors, and all three implementations together.

### API (`api/app.py`)

Three endpoints, no authentication, no rate limiting, and `CORS(app)` wide open with no options.

| Route | Behaviour |
|---|---|
| `POST /api/secrets` | Body `{ciphertext, ttl_hours?, id?}` → `201 {id, alias}`. |
| `GET /api/secrets/<secret_id>` | `secret_id` is a UUID **or** an 8-char base62 alias → `200 {ciphertext, id}`; `404` when already viewed. |
| `GET /api/health` | Pings Redis. `200 {"status":"ok"}` or `503 {"status":"degraded"}`. |

Details that are easy to get wrong:

- **The secret ID is generated client-side and posted**, because the client needs it as both HKDF `info` and GCM AAD. The server generates one only when `id` is omitted (backwards compatibility).
- **`GET` always returns the UUID**, but the client must use the **URL path segment** (the alias, when one exists) for AAD and HKDF. The alias is presentation-only.
- Redis keys: `secret:{uuid}` written with `SETEX`; `alias:{8char}` written with `SET … NX` (atomic, up to 5 collision retries; a total failure still returns the secret with `alias: null`). Retrieval is a single **`GETDEL`** — that is the one-time guarantee.
- `MAX_CIPHERTEXT_SIZE` is **40 MB**, measured in characters of the base64 string. `ttl_hours` is **clamped, not rejected**: `max(1, min(72, ttl_hours))`.
- Error responses are `{"error": "..."}`, with the exact messages asserted in `test_app.py`.

### Logging (`api/logging_config.py`)

One JSON object per line on stdout, UTC timestamps. The field order is a **cross-app contract** (shared byte-for-byte with another internal app) and is deliberately fixed:

```
levelname asctime name message tenant_id tenant_name user_id user_email request_id task_id
```

Only `request_id` is populated here; the rest are present-but-empty rather than `null`. `test_app.py` asserts that no base64 payload ever appears in the log stream.

### UI (`ui/`)

- **Routing** is inline in `ui/src/main.tsx` — no separate routes file. `main.tsx` always uses `createRoot`, never `hydrateRoot`: prerendered HTML is for crawlers only, and hydrating would produce i18n mismatch errors.
- **Styles** are CSS custom properties. `src/index.css` is a six-line `@import` chain into `src/styles/*.css`; `tokens.css` holds the `:root` token block and the self-hosted `@font-face` declarations. The theme is dark-only; a future `[data-theme="light"]` block is expected to override the same `--*` names.
- **Build is two-stage**: `npm run build:prerender` = `tsc -b && vite build && node scripts/prerender.mjs`. The prerender script drives headless Puppeteer over every route in `dist/sitemap.xml` (plus a hardcoded noindex list) and writes per-route `index.html` files. This is why `ui/Dockerfile` installs Chromium.
- **TypeScript is strict with `noUnusedLocals` and `noUnusedParameters`**, and `npm run build` runs `tsc -b` — unused locals fail the build.
- There is **no ESLint or Prettier** anywhere in the repo.
- `vite-plugin-sri` adds integrity attributes to built assets.

### Extension (`extension/`)

Shares `ui/src` through `wxt.config.ts` (`resolve.alias["@ui"]`) and `tsconfig.json` (`@ui/*`). It reuses `@ui/lib/crypto` and `@ui/i18n/locales` directly, so **it must be built with `ui/node_modules` present** — `release-extension.yaml` runs `npm ci --omit=dev --prefix ../ui` for exactly this reason. `extension/vitest.config.ts` sets `resolve.dedupe` for react/react-dom/motion so `@ui` components don't pull a second React copy and break hook dispatch.

The manifest requests only `contextMenus, activeTab, scripting, storage, clipboardWrite` and host permissions for `ooshare.io` / `api.ooshare.io` — never broad `<all_urls>`.

### CLI (`cli/`)

`ooshare create [flags]` and `ooshare view <url>`. **Exit codes: `0` success, `1` runtime/API error, `2` usage error.** Flag defaults fall back through `--flag` → env (`OOSHARE_API_URL`, `OOSHARE_ORIGIN`) → built-in. `--json` emits a `{"schema":1,…}` document. Attachments are capped at 25 MB and the accepted MIME list mirrors `FileDropzone.ACCEPTED_TYPES` in the UI.

## CI

`ci.yaml` runs on **pull requests to `main` only** — there is no push-to-main CI. `e2e.yaml` runs on push to `main` and exercises 11 create/view scenarios against the API through the external `dhdtech/ooshare-action@v1`.

| Suite | Gate |
|---|---|
| API | `--cov-fail-under=99` |
| UI | `--coverage.thresholds.lines=99` |
| CLI | 90% total statement coverage (enforced by an `awk` check in CI, not in the Makefile) |
| Extension | 90% lines / 80% branches — defined in `extension/vitest.config.ts`, but **no CI job runs it** |

`make test` and `make ui-test` do **not** enforce the thresholds; only CI does.

**`extension/` has no CI job at all**, despite having its own release workflow.

## Build Constraints That Bite

- **The CSP forbids `unsafe-inline` for scripts.** `ui/nginx.conf` allows the three inline scripts in `ui/index.html` (gtag, Meta pixel, and an ad snippet) only by exact SHA-256 hashes. Changing a single character or leading whitespace invalidates the hash and the script is silently blocked until the hash is recomputed. The scripts are kept flush-left for hash stability.
- **All security headers live in `ui/nginx.conf`**, not in the API. The Flask app sets no security headers and no CORS restrictions of its own.
- `nginx.conf` routes `/s/` to the SPA fallback but `/` to `try_files … =404` — unknown paths correctly 404 because every real route is prerendered.
- **`release-cli.yaml` triggers on `v*` tags.** A `cli/v*` tag (used for Go module versioning) will **not** trigger a release.
- **The `plans/` directory is finished work**, not a backlog. `plans/README.md` states all 11 plans are `DONE`.

## i18n

Six languages: `en, zh, es, hi, ar, pt`. UI locale files in `ui/src/i18n/locales/*.json`, statically imported (no lazy loading). Detection order `querystring → localStorage → navigator`; the `?lng=` parameter is also what the SEO hreflang links use. The extension reuses the same JSON files with a `localStorage → navigator` order.

**Blog translations are a separate mechanism.** English posts live in `ui/src/content/blog-posts.ts`; translations are TS modules in `ui/src/content/blog/{es,zh,pt,hi,ar}.ts` merged through a `translationMap`. Blog bodies are HTML strings, not i18n keys.

Every user-facing string and every content page must exist in all six languages.
