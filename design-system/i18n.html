i18n

Internationalization

The product is translated into six languages via i18next. Every copy string lives in a JSON bundle per locale, and the language is detected automatically. RTL layout hooks exist in the CSS but are not yet wired up to auto-flip.

Language switcher

A circular 36px trigger with the flag, and a dropdown of the six options.

Selecting a language writes it to localStorage.i18nextLng; the content re-renders without a reload.

RTL (Arabic)

Arabic is an RTL script, and the design system reserves a [dir="rtl"] hook. Today only one rule uses it. 

/* ui.css — the only RTL-aware rule today */
[dir="rtl"] .ui-toast-viewport { ... }
⚠️
Known gap. The app does not currently set document.documentElement.dir = "rtl" when Arabic is active, so Arabic renders left-to-right today. The [dir="rtl"] class hooks are the groundwork — flipping the document direction (and auditing alignment/logical properties) is an open follow-up.

Design implications

✓
Logical properties. Components should use margin-inline / padding-inline / inset-inline and text-align: start, so a future RTL flip needs no per-component overrides. The kit's mono/label types rely on the same --font-sans stack.
✕
Don't — hard-code left/right in a new component when an inline/logical equivalent works; it breaks the moment RTL is enabled.
